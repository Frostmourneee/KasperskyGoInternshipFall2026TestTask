# Threat Information Service

REST-сервис на Go для хранения и обмена сведениями об угрозах. Позволяет создать запись, получить её по MD5 файла и обновить данные. Сведения об угрозе и её опасности передаёт клиент.

Проект выполнен как тестовое задание для стажировки Go-разработчика.

## Стек технологий

| **kin-openapi** | Проверка входящих запросов по OpenAPI-схеме |

| **pgx/v5** | Драйвер PostgreSQL и пул соединений |

| **golang.org/x/time/rate** | Ограничение частоты запросов к экземпляру сервиса |
| **slog** | Структурированные JSON-логи в stdout |
| **Docker, Docker Compose** | Сборка и совместный запуск API, мигратора и БД |

| **gofmt, go vet** | Форматирование и статический анализ кода |

## Архитектура и логика работы

Запрос проходит через проверку API-ключа, ограничений и схемы, затем попадает в сервис угроз и PostgreSQL-хранилище. HTTP-слой отвечает за запросы и ответы, сервис — за правила работы с данными, хранилище — за SQL.

```text
api/                          # OpenAPI-контракт и настройки генерации
cmd/server/                   # Запуск HTTP-сервера
cmd/migrate/                  # Запуск миграций
internal/config/              # Настройки из переменных окружения
internal/threat/              # Модель угрозы и сервис
internal/transport/httpapi/    # HTTP-обработчики и middleware
internal/storage/postgres/    # Хранилище, SQL-запросы и код sqlc
migrations/                   # Миграции схемы БД
tests/unit/                   # Юнит-тесты
tests/integration/            # Интеграционные тесты и тестовая БД
```

- `POST /info` — создать запись. Повторный MD5 возвращает `409`.
- `GET /info/{md5}` — получить запись. Если её нет, возвращается `404`.
- `PUT /info/{md5}` — полностью заменить данные существующей записи. Пропущенные необязательные поля сбрасываются в значения по умолчанию.

MD5 хранится в нижнем регистре. Все операции требуют заголовок `X-API-Key`; запись данных — `Content-Type: application/json`. Полный контракт: [api/openapi.yaml](api/openapi.yaml).

### Добавленные поля

К исходным `md5` и `name` добавлены:

| Поле | Назначение |
| --- | --- |
| `description` | Текстовое описание угрозы; по умолчанию пустая строка |
| `threat_type` | Категория угрозы, например `trojan` или `ransomware`; по умолчанию `unknown` |
| `severity` | Уровень опасности: `unknown`, `low`, `medium`, `high` |
| `file_size` | Размер файла в байтах; `null` означает неизвестный размер, `0` — пустой файл |
| `created_at` | Время создания записи для отслеживания её появления |
| `updated_at` | Время последнего изменения данных для определения их актуальности |

Временные метки задаёт сервер в UTC. Повтор одинакового PUT сохраняет `updated_at`.

## Быстрый старт

Нужны Docker с Compose v2, `make`, OpenSSL и `curl`. Go для запуска в Docker устанавливать не требуется.

```bash
# 1. Клонировать репозиторий
git clone https://github.com/Frostmourneee/KasperskyGoInternshipFall2026TestTask.git
cd KasperskyGoInternshipFall2026TestTask

# 2. Создать локальный файл настроек
cp .env.example .env

# 3. Сгенерировать два разных секрета
openssl rand -hex 32  # Значение POSTGRES_PASSWORD
openssl rand -hex 32  # Значение API_KEY
```

Впишите полученные значения в соответствующие поля `.env`, затем запустите сервис:

```bash
make up
```

Compose соберёт приложение, дождётся готовности PostgreSQL, применит миграции и запустит API на `http://localhost:8080`. HTTP-порт доступен только на локальном компьютере. Спецификация находится в файле OpenAPI; Swagger UI в сервисе не подключён.

Проверка API из корня проекта в Bash:

```bash
# Загрузить API_KEY из своего .env
. ./.env

# Создать запись — ожидается 201 Created
curl -i -X POST http://localhost:8080/info \
  -H "X-API-Key: $API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"md5":"d41d8cd98f00b204e9800998ecf8427e","name":"Example.Threat","threat_type":"trojan","severity":"low","file_size":0}'

# Получить запись — ожидается 200 OK
curl -i http://localhost:8080/info/d41d8cd98f00b204e9800998ecf8427e \
  -H "X-API-Key: $API_KEY"
```

Повторное создание этой записи вернёт `409 Conflict`.

```bash
make logs  # Смотреть логи API и мигратора
make down  # Остановить контейнеры, сохранив данные PostgreSQL
```

Уровень логов задаётся через `LOG_LEVEL` в `.env`: `debug`, `info`, `warn`, `error`. В логах запросов сохраняются метод, шаблон маршрута, статус и длительность. API-ключи и тела запросов не записываются.

## Тесты и разработка

Для этих команд нужен Go **1.27.1 или новее**. Команды выполняются из корня проекта.

```bash
make test             # Юнит-тесты; также доступны через make test-unit
make test-db-up       # Запустить отдельную одноразовую PostgreSQL
make test-integration # Интеграционные тесты с реальными миграциями
make test-db-down     # Удалить тестовую БД

make generate         # Перегенерировать HTTP-код и SQL-код
make fmt              # Отформатировать Go-код
make vet              # Статический анализ
make build            # Собрать bin/server и bin/migrate
```

Тестовая БД доступна на `127.0.0.1:15432` и хранит данные в памяти. Интеграционные тесты работают в отдельной схеме; другую тестовую БД можно указать через `TEST_DATABASE_URL`.

## Что можно было бы добавить

- **Prometheus и Grafana** — метрики количества запросов, задержек и ошибок, дашборды и оповещения.
- **CI** — автоматический запуск тестов, статического анализа и сборки Docker-образа при изменении кода.
- **Поиск и фильтрацию** — получение списка угроз по типу и уровню опасности с пагинацией.
- **HTTPS и отдельные API-ключи с правами** — доступ по сети и разделение операций чтения и записи.
